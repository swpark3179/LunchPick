# 점심픽 (LunchPick)

점심 식당을 모아두고, 오늘 어디 갈지 여러 방식으로 줄여서 정하는 Windows 데스크탑 앱.

- **식당 목록** — 식당·메뉴·전화번호 관리, 분류/★ 필터, 카드·표 보기, 전화번호 복사
- **오늘 뭐 먹지?** — 소거법 · 이상형 월드컵 · 사다리 타기 · 룰렛 · 슬롯머신 · AI 추천.
  한 가지 방식으로, 또는 여러 방식을 코스로 이어서 후보를 줄인다.
- **같이 고르기** — 사내망의 동료와 한 화면을 보며 실시간으로 함께 고른다. 가기 싫은 곳 빼기,
  후보 함께 찍기, 무작위 n곳 뽑기, AI 정렬(대기열·멀티턴), 사다리, 하트 걸기(선호도 모으기), 최종 확정,
  확정한 식당에서 각자 메뉴 고르기(늘 먹는 메뉴 자동 담기), 예약 완료 공유, 채팅(리액션), 식당 목록 동기화·삭제.
- **도란식사 정하기** — 같이 고르기와 같은 방에서, 회식·모임 식당을 방 안에서 함께 입력하고 식당 + 메뉴 구성으로
  '선택지'를 만들어 무작위·사다리·하트로 좁힌다. 총사용금액 대비 남음/딱 맞음/초과를 보여 주고, 확정하면 누군가 예약한다.
  방에 올라온 식당은 각자 PC에 식당마다 파일 하나로 저장돼 다음에 골라 불러온다.
- **설정** — 실시간 공유 서버(호스트 열기 / 참여), FabriX(AI) 키 등록, 표시 옵션,
  식당 목록 JSON 내보내기/가져오기, CSV 내보내기, 샘플로 초기화 / 모두 지우기

## 기술 스택

Tauri 2 · React 19 · TypeScript · Vite · Zustand / Rust (reqwest · keyring · tokio-tungstenite)

## 개발

```bash
npm install
npm run tauri dev      # 앱 실행
npm run build          # 타입체크 + 프론트엔드 빌드
npm run tauri build    # 실행 파일 생성 → src-tauri/target/release/lunchpick.exe
```

`npm run dev` 만 띄우면 브라우저에서도 UI를 볼 수 있다 (저장은 localStorage로 폴백, AI·파일
다이얼로그는 동작하지 않음).

## 배포 — 설치 없이 exe 하나로

`lunchpick.exe` 파일 하나만 복사해서 아무 폴더에서나 실행하면 된다. 화면(HTML·JS·폰트)과
VC++ 런타임, WebView2 로더가 모두 exe 안에 들어 있다. 설치 파일(NSIS)은 만들지 않는다
(`tauri.conf.json` 의 `bundle.active: false`).

- **필요한 것** — Microsoft Edge WebView2 런타임. Windows 11 에는 기본으로 있고, Windows 10 도
  Edge 가 깔린 PC 는 대부분 있다. 없으면 창이 뜨지 않는다.
- **데이터는 exe 옆이 아니라 사용자 폴더에 저장된다** (아래 '저장 위치'). 그래서 새 버전 exe 로
  바꿔도 식당 목록과 키가 그대로 남는다. 화면 캐시는 `%LOCALAPPDATA%\com.lunchpick.desktop` 에 생긴다.
- **코드 서명이 없다** — 메일·메신저로 받은 exe 는 Windows SmartScreen 이 "PC 보호" 경고를 띄울 수
  있다. `추가 정보 → 실행` 으로 연다.
- **지우기** — exe 와 `%APPDATA%\com.lunchpick.desktop`, `%LOCALAPPDATA%\com.lunchpick.desktop`
  폴더를 지우고, 자격 증명 관리자에서 `lunchpick` 항목을 지운다.

## 저장 위치

| 대상 | 위치 |
|---|---|
| 식당·메뉴·먹은 기록·늘 먹는 메뉴 | `%APPDATA%\com.lunchpick.desktop\data.json` |
| 설정 (비밀값 제외) | `%APPDATA%\com.lunchpick.desktop\settings.json` |
| 도란식사 식당 보관함 (식당마다 파일 하나) | `%APPDATA%\com.lunchpick.desktop\doran\<식당 id>.json` |
| FabriX 자격증명 | Windows 자격 증명 관리자 — 서비스 `lunchpick` |

설정 화면 하단에 실제 저장 경로가 표시된다. 두 JSON 파일은 임시 파일 + rename 으로 원자적으로
쓴다. 파일이 손상되면 `*.corrupt.json` 으로 치워두고 샘플 데이터로 시작한다.

## AI 추천 (FabriX)

Samsung SDS FabriX **LLM Serving APIs** 를 쓴다. FabriX 포털에서 신청하면 받는 값 3개를 설정
화면에 넣는다.

| 입력 | 보내는 헤더 |
|---|---|
| Endpoint URL | — (`{endpoint}/openapi/llm` 이 base) |
| Client Key | `x-fabrix-client` |
| OpenAPI Token | `x-openapi-token` (`Bearer ` 접두사는 없으면 자동으로 붙음) |
| 모델 | `x-llm-model-id` (기본 `16`) |

호출은 **Rust 백엔드에서만** 한다 — 키가 webview 로 내려가지 않고, 키를 읽는 Tauri 커맨드도
없다. AI 가 실패하면(키 미설정·네트워크 오류·한도 초과·응답 파싱 실패) 무작위 선택으로 폴백해
흐름이 막히지 않는다.

FabriX 호출은 **프록시를 타지 않고 항상 DIRECT** 로 나간다. PC 에 `HTTP_PROXY`·`HTTPS_PROXY`·
`ALL_PROXY` 환경변수나 Windows 인터넷 옵션 프록시가 잡혀 있어도 무시한다.

**키 없이 테스트하기** — 바탕화면 `FabrixSample` 에 실 응답을 재생하는 목 서버가 있다.

```bash
cd ~/Desktop/FabrixSample
pip install requests          # 목 서버가 쓰는 fabrix 패키지에 필요
python -m mock.server --port 8765
```

설정 화면에 아래 값을 넣으면 된다.

```
Endpoint URL : http://127.0.0.1:8765/sds/trial/api-llm
Client Key   : mock-client-key
OpenAPI Token: Bearer mock-openapi-token
```

## 같이 고르기 (실시간 공유)

한 사람이 **호스트**로 공유 서버를 열고, 나머지는 각자 PC의 점심픽에서 그 주소로 **접속**한다.
식당 목록과 AI 정렬은 호스트 PC 기준이다(참여자끼리 목록을 맞추려면 방에서 **식당 동기화**). 화면과
애니메이션은 디자인 시안 `같이 고르기.dc.html` 을 따른다.

1. 설정 → 실시간 공유 서버에서 **내 이름**을 정한다. 아바타 색은 이름에서 정해지고, 오른쪽에
   '동료 화면에는 이렇게 보여요' 미리보기가 뜬다.
2. 호스트: **호스트로 열기** → 포트(기본 `8787`) → **서버 켜기**. 포트 확인 → 로컬 서버 시작 →
   식당 공유 준비 단계가 차례로 지나가고, 레이더 가운데의 나와 둘레로 들어오는 동료, 크게 보이는
   접속 주소(복사)가 나온다. 처음 켤 때 Windows 방화벽 창이 뜨면 '허용'을 누른다.
   '자동 시작'을 켜 두면 앱을 켤 때 서버도 함께 열린다.
3. 참여자: **호스트에 접속** → `주소:포트` → **접속**. 호스트 찾는 중 → 연결 확인 → 식당 정보 받는
   중(k/N) → 입장 준비를 거쳐 잠시 뒤 같이 고르기 화면으로 들어간다. 한 번 들어간 방은 **방 찾기**
   목록에 호스트 이름과 함께 남는다(최대 20곳). 목록은 보일 때와 20초마다(또는 '다시 찾기') 각 방이 지금
   열려 있는지 들어가지 않고 확인해서 'n명 접속 중 / 닫혀 있어요'를 보여주고, 열린 방은 **입장**으로 바로
   들어간다. 더 쓰지 않는 주소는 ✕ 로 지운다.
4. 같이 고르기 화면에서는 사이드바가 접히고 방이 넓게 열린다. 머리의 진행 표시
   (가기 싫은 곳 빼기 → 후보 올리기 → 추려내기 → 최종 확정 → 메뉴 고르기 → 예약 완료)가 지금 단계를
   알려준다. 확정 전에는 앞의 네 단계만, 확정 뒤에는 뒤의 세 단계만 보인다.

방에서 할 수 있는 것 — 식당 세부정보를 빼면 모두 **같은 화면**으로 공유된다.

| 기능 | 동작 |
|---|---|
| 가기 싫은 곳 | 카드의 ⊘ → 그 자리에서 작아지며 빠지고 왼쪽 열에 빠진 순서대로 쌓인다. 누가 뺐는지 보이고, '내 표시 취소'·'나도 싫어요'로 표를 더하거나 뺀다. 아무도 싫어하지 않으면 다시 목록으로 |
| 후보 | 카드를 누르면 모두에게 '후보 · 이름'으로 표시. 한 번 더 누르면 내려온다 |
| 보는 중 | 다른 사람이 마우스를 올린 카드에 그 사람의 이름표가 따라다니고, 참여자 목록에 '보는 중 · 식당'이 뜬다 |
| 무작위 n곳 | 스포트라이트가 카드 사이를 건너뛰다 느려지며 n곳(최대 5)에 멈추고, 그곳들이 후보로 올라간다 |
| AI 정렬 | 원하는 걸 말하면 호스트의 AI가 **순서만** 다시 늘어놓는다 — 카드가 새 자리로 미끄러지고 ▲▼로 오르내린 칸 수, 앞 3곳에 'AI n위'가 붙는다. 원문은 호스트의 AI에만 가고 다른 사람에게는 **키워드만** 공개된다(내 원문은 내 칩의 툴팁·팝업에만). 여러 명이 보내면 'AI 큐'에 들어온 순서대로 쌓여 한 대화(멀티턴)로 누적 반영된다(1차, 2차 …). '순서 초기화'로 모두 되돌린다 |
| AI 큐 | 칩을 누르면 그 요청이 매긴 **1~5위**(이유·지금 상태 포함)가 팝업으로 뜬다. '이 요청 지우기'는 그 요청만 빼고 남은 요청들로 순서를 다시 쌓는다 — 마지막 요청이면 그 직전 순서로 돌아가고, 다음 AI 정렬의 대화 맥락·#태그 강조에서도 빠진다. 대기·정렬 중인 요청은 취소된다. 누가 지웠는지 채팅에 남는다 |
| 사다리 | 후보 2~8곳 중 n곳을 남긴다. 모두에게 같은 사다리가 보이고, 누구든 이름을 눌러 한 줄씩 또는 '전체 출발'로 내려보낸 뒤 '결과 적용'을 누른다 |
| 하트 걸기 | 후보 2~6곳에서 어디를 더 원하는지 모은다. 각자 하트 3개를 후보 칸의 +/− 로 나눠 건다 — 한 곳에 몰면 그만큼 더 가고 싶다는 뜻이고, '아무데나 좋아요'로 빠질 수도 있다. 건 하트는 건 사람 색으로 바로 모두에게 보인다(내 하트는 트레이에서 날아가고, 남의 하트는 떨어져 앉는다. 2곳이면 시소가 기운다). 누구든 '마감하기'를 누르면(아직 덜 건 사람이 있으면 두 번) 칸이 순위 자리로 미끄러지고 1위에 왕관이 뜬다. **무작위가 없고 결과는 참고용**이다 — 동점은 '공동 1위'로 두고, 어느 후보든 그 자리에서 확정하거나 '동점끼리 한 번 더' · '♥0 후보 내리기' · '다시 걸기' · '닫기'를 고른다. 자동 마감은 없고, 닫아도 후보 칩에 받은 하트(♥n)가 남는다. 방 가운데만 덮어서 채팅·식당 정보는 그대로 쓸 수 있다 |
| 최종 확정 | 누구든 후보 칩의 '확정'(또는 식당 정보의 '이 식당으로 최종 확정')을 누르면 모두에게 색종이와 함께 결과가 뜬다. 호스트의 먹은 기록에 남고, '다시 고르기'로 모두에게서 풀 수 있다(예약이 있으면 먼저 예약을 취소한다). 닫으면 머리에 '오늘은 …'이 남고, 가운데는 메뉴 고르기로 바뀐다 |
| 메뉴 고르기 | 확정한 식당의 메뉴마다 −/+ 로 각자 먹을 메뉴와 수량을 고른다(여러 개 가능, 목록에 없는 메뉴는 직접 적기). 누가 무엇을 골랐는지 메뉴 옆 아바타와 '모두의 메뉴'(사람별 · 합계 · 금액)로 모두에게 같이 보이고, 복사할 수 있다. 다른 식당으로 다시 확정하거나 확정을 풀면 비워진다. 그 식당에 **늘 먹는 메뉴**를 정해 뒀으면 확정되는 순간 각 1개씩 자동으로 담기고(아직 고른 게 없고 예약 전일 때, 확정마다 한 번) 그 줄이 잠깐 빛난다. 이미 골랐거나 예약 뒤라면 '늘 먹는 메뉴 담기'로 직접 담는다 |
| 예약 완료 | 식당에 예약하는 사람이 '예약하기'를 누르면 다른 사람들에게 '○○님이 예약하는 중'이 뜨고, 그때 다른 사람이 '예약하기'를 누르면 한 번 더 묻는다. 예약 화면은 모두가 고른 메뉴의 합으로 채워져 있어 실제로 예약한 대로 메뉴·개수를 고치고 특이사항을 적어 '예약 완료'를 누른다. 모두에게 예약 알림(메뉴 × 개수 · 합계 · 특이사항 · 내가 고른 메뉴)이 뜨고 채팅에 한 줄 남는다(방 밖이면 토스트). 예약을 고치거나 취소하는 건 예약한 사람과 호스트만 한다. 예약 뒤에도 각자 메뉴는 바꿀 수 있고, 바뀌면 예약 카드에 '예약 뒤에 바뀐 메뉴' 와 바꾼 사람에게 '예약 뒤 바꿈' 이 붙는다 |
| 채팅 | 기본 채팅 + 입력 중 표시. 말풍선 옆에 보낸 시각(같은 사람이 같은 분에 이어 보내면 마지막에만). 빼기·올리기·뽑기·정렬·사다리·확정·정보 수정·삭제·동기화도 한 줄씩 남는다 |
| 채팅 리액션 | 다른 사람 말풍선에 마우스를 올리면 ⭕네 · ❌아니요 · 👍좋아요 · 🙏고마워요 · 😊웃음 · 😮놀람 · 😅당황 · 😢눈물 · ✅확인 줄이 뜬다. 고르면 말풍선 아래에 칩(👍 2)으로 모두에게 보이고, 다시 누르면(줄이나 칩에서) 뗀다. 칩에 마우스를 올리면 누른 사람이 보인다. 내 말풍선에는 달 수 없고, 채팅 줄은 남지 않는다 |
| 채팅 알림 · 조용히 | 다른 사람이 채팅을 보냈을 때 점심픽 창을 보고 있지 않으면 작업표시줄에서 깜박인다(창을 앞으로 가져오면 멈춘다). 오른쪽 열(참여자 · 채팅) 위의 **조용히**를 켜면 내 PC에서는 깜박이지 않는다 — 설정에 남고, 부르기는 그대로 온다 |
| 부르기 | 참여자 목록에서 이름에 마우스를 올리면 '부르기'가 보인다. '상대가 놀랄 수 있어요' 확인(확인/취소)을 거치면 그 사람 PC에서 점심픽 창이 **한 번** 맨 앞으로 뜨고(최소화돼 있으면 되살린다) '○○님이 불렀어요' 창이 뜬다. 누가 누구를 불렀는지 채팅에 남고, 같은 사람은 30초가 지나야 다시 부를 수 있다 |
| 식당 동기화 | 누구든 머리의 '식당 동기화'를 누르면 모두에게 수락/거절 알림이 뜬다. 수락한 사람끼리 식당 목록을 **합집합**으로 맞춘다 — 이름이 같은 식당은 하나로 보고 없는 메뉴와 비어 있는 전화번호·메모만 채우며, 있던 정보는 그대로 둔다. 방 목록은 호스트 목록이라 **호스트가 수락해야** 합쳐지고(거절하면 취소), 호스트가 수락한 뒤로는 들어오는 대로 방 목록에 바로 더해진다. 모두 답하거나 1분이 지나면 끝나고(답하지 않으면 거절), 수락한 참여자는 합쳐진 목록을 각자 받는다 |
| 식당 삭제 | 식당 정보 드로어의 '삭제' → 확인하면 호스트 목록에서 지워지고, 방에 있던 참여자들의 식당 목록에서도 (이름이 같은 식당까지) 지워진다. 확정된 식당·사다리에 오른 식당·뽑는 중에는 지울 수 없다 |

식당 **세부정보**(메뉴·전화번호·메모)는 '나만 보는 중' 드로어로 각자 연다. 틀린 정보는 '정보 수정'으로
고치면 호스트의 식당 목록에 저장되고, 모두에게 '방금 수정됨'과 채팅 한 줄로 알려진다. 없어진 식당은
'삭제'로 모두의 목록에서 지운다.

호스트 PC에 FabriX 키가 없거나 AI 호출이 실패하면 키워드 사전(국물·안 매운·가볍게·비 오는 날 …)으로
대신 정렬해 흐름이 막히지 않는다(나중 요청일수록 조금 더 무겁게 친다). 호스트는 참여자 목록에서
**내보내기**를 할 수 있고, **서버 끄기**를 누르면 참여자들에게 종료 안내가 간다. 호스트가 **점심픽을 닫아도**
(✕ · Alt+F4 · 작업표시줄 닫기) 같은 안내('호스트가 점심픽을 종료했어요.')가 가고 참여자의 방이 바로 끝난다 — 서버를 켤 때
작별 인사를 Rust 에 맡겨 두고, 앱이 꺼질 때(`RunEvent::Exit`) Rust 가 그걸 보낸 뒤 연결을 닫는다. 참여자는 연결이 잠깐
끊기면 같은 사람으로 자동 재접속한다. 다시 붙는 중에 '연결 거부'(그 주소에 서버가 없음)가 두 번 이어지면 호스트가 앱을
껐다고 보고 기다리지 않고 끝낸다(작업 관리자로 강제 종료한 경우 등).

**구조** — Rust(`src-tauri/src/share.rs`)는 WebSocket 서버/접속과 텍스트 전달만 한다. 방 상태의 주인은
호스트 PC의 프론트엔드(`src/share/host.ts`)이고, 참여자는 요청(Action)을 보내고 호스트가 적용한 상태
전체를 받는다. '보는 중' 표시는 자주 바뀌어서 작은 메시지로 따로 보낸다. 메시지 모양은
`src/share/protocol.ts` 에만 있다. 같은 사내망 안에서만 쓰는 기능이라 암호화(TLS)·입장 코드는 없다.

**애니메이션** — 키프레임은 시안의 `lp-*` 를 그대로 옮겼다(`src/styles/together.css`, 하트 걸기의 `lp-drop` ·
`lp-beat` · `lp-burst` 만 시안 밖이다). 무작위 뽑기·사다리·하트 걸기는 연출 자체가 기능이라 `.keep-motion` 으로
감싸 Windows '애니메이션 효과'를 꺼 둔 PC에서도 보인다. 시간표(`src/share/anim.ts`)는 모든 화면이 같은 값으로
계산하고, 호스트의 '애니메이션 속도'를 따른다(하트 걸기는 호스트가 기다리는 연출이 없어 각자의 속도를 따른다).

**개발 모드에서 확인하기** — `npm run dev` 로 띄운 브라우저에서는 같은 브라우저의 탭끼리
BroadcastChannel 로 흉내 낸다. 한 탭에서 서버를 켜고, 다른 탭에서 `아무주소:같은포트` 로 접속한다.

## 도란식사 정하기

회식·모임처럼 점심 목록에 없는 식당을 정할 때 쓴다. 설정 › 실시간 공유 서버에서 **호스트로 열기** → 열 방을
**도란식사 정하기**로 고르고 **도란식사 방 열기**. 참여자는 점심 방과 똑같이 `주소:포트` 로 접속한다(방 종류는 호스트가 정한다).
방 찾기 목록에는 '…님의 도란식사 방'으로 보인다. 자동 시작은 늘 점심 방이다.

방은 같이 고르기와 같다 — 오른쪽 참여자·채팅(리액션·부르기·조용히), 실시간 공유, 사다리·하트 걸기·확정·예약 창. 다른 점은:

| 영역 | 동작 |
|---|---|
| 식당 (왼쪽) | 누구든 **+ 식당 추가**로 이름·분류·전화·메모·메뉴(가격, 모르면 비워서 '가격 미정')를 적어 올리고, 식당을 눌러 고치거나 지운다(지우면 그 식당의 선택지도 함께). 이름이 같은 식당은 하나만. **불러오기**는 내 PC 보관함에서 몇 곳만 골라 올린다(이미 방에 있는 식당은 고를 수 없다) |
| 선택지 | 식당만, 또는 식당 + 메뉴 구성(메뉴마다 수량, 목록에 없는 메뉴는 가격과 함께 직접 적기)으로 만든다. 같은 식당으로 구성을 달리해 여러 개 만들 수 있고(같은 구성은 막는다), 이름('회 코스')·메모를 붙일 수 있다. 'A안·B안 …'으로 부르고, 지워도 다시 쓰지 않는다. 메뉴 가격이 나중에 정해지면 그 식당 선택지들의 합계가 따라 바뀐다 |
| 총사용금액 | 가운데 위에 누구든 적는다. 선택지마다 **n원 남아요 · 딱 맞아요 · n원 초과**를 보여 주고, 가격 미정 메뉴가 끼면 합계는 '확정 금액 + α', 비교는 '+α가 n원 안이면 맞아요' / '+α만큼 초과'로 보인다 |
| 좁히기 | 만든 선택지는 바로 후보다. **빼기**로 아래 '빠진 선택지'로 내리고 **다시 넣기**로 되살린다. **무작위 n개 남기기**는 남은 선택지 위를 스포트라이트가 건너뛰다 n개에 멈추고 나머지를 뺀다. **사다리**(8개 이하)·**하트 걸기**(6개 이하)는 점심 방과 같다 |
| 확정 · 예약 | 카드나 하트 걸기 결과에서 **확정** → 모두에게 확정 화면. 각자 메뉴 고르기는 없고, 가운데에 확정된 선택지(메뉴·합계·예산 비교·전화)가 남는다. 식당에 예약한 사람이 **예약하기**(선택지 메뉴로 채워져 있다)에서 실제로 예약한 대로 고쳐 알린다. 고치기·취소는 예약한 사람과 호스트만. 먹은 기록은 남기지 않는다 |

**식당 보관함** — 도란식사 방에 올라온(고쳐진) 식당은 호스트·참여자 모두 각자 PC에 자동으로 저장된다.
식당마다 `doran\<식당 id>.json` 파일 하나라서 하나가 깨져도 나머지는 그대로 읽힌다(깨진 파일은 건너뛴다).
내용이 그대로면 다시 쓰지 않고, 다른 PC에서 따로 입력한 같은 이름의 식당은 새 것으로 바꾼다. 불러오기 창에서
더 쓰지 않는 식당을 지운다(방에 올라간 식당은 그대로). 점심 식당 목록(`data.json`)·먹은 기록과는 따로라서 도란식사 방은
내 점심 목록을 건드리지 않는다.

## 식당 목록 공유

설정 → 데이터에서 JSON으로 내보내고, 받은 파일을 그대로 가져올 수 있다.

```json
{
  "format": "lunchpick.restaurants",
  "version": 1,
  "exportedAt": "2026-10-06T03:00:00.000Z",
  "count": 27,
  "restaurants": [{ "id": "…", "name": "진주집", "category": "한식", "phone": "02-555-1234",
                    "memo": "", "fav": true,
                    "menus": [{ "id": "…", "name": "김치찌개", "price": 9000, "fav": true }] }]
}
```

가져올 때 두 가지를 고를 수 있다.

- **합치기** — 식당 이름 기준으로 매칭. 새 식당만 추가하고, 겹치는 식당에는 없는 메뉴만 더한다.
  기존 전화번호·메모·★ 는 보존한다.
- **전체 교체** — 지금 목록을 파일 내용으로 완전히 바꾼다.

먹은 기록(`history`)과 늘 먹는 메뉴(`myMenus`)는 개인 데이터라 내보내지 않는다.

## 늘 먹는 메뉴

'이 식당이면 나는 이 메뉴'를 내 PC에 정해 둔다. 식당 목록의 식당 드로어(또는 같이 고르기의 식당 정보)에서
메뉴 옆 **늘 먹는** 을 켜면 된다(식당마다 여러 개). 같이 고르기에서 그 식당이 확정되면 메뉴 고르기에 각 1개씩
자동으로 담긴다. 설정 › 표시 / 동작에서 끌 수 있다.

- `data.json` 의 `myMenus` 에 식당 이름 → 메뉴 이름으로만 저장한다. 식당 목록(`restaurants`)과 따로 두어서
  같이 고르기 방·**식당 동기화**·JSON/CSV 내보내기 어디로도 나가지 않는다(골라 둔 메뉴 자체는 원래처럼 방에 보인다).
- 참여자 목록은 호스트와 id 가 달라서 이름으로 맞춘다. 내 목록에서 식당·메뉴 이름을 바꾸면 따라 바뀌고, 지운 메뉴는
  빠진다. 확정된 식당의 메뉴에 없는 이름은 직접 입력으로 만들지 않고 건너뛴 뒤 토스트로 알린다.
- ★(대표 메뉴)는 식당 정보라 공유되지만, 늘 먹는 메뉴는 나만의 표시다.

같은 카드의 **샘플 데이터로 초기화**는 목록을 샘플 27곳으로 되돌리고, **식당 목록 모두 지우기**는 샘플까지
포함해 식당과 먹은 기록·늘 먹는 메뉴를 전부 지운다(빈 목록도 그대로 저장돼 다음 실행 때 샘플이 다시 생기지 않는다).
둘 다 한 번 더 눌러야 실행된다.

## 애니메이션

일반 UI 전환은 Windows의 '애니메이션 효과' 설정(`prefers-reduced-motion`)을 따른다.
고르기 엔진(룰렛·사다리·슬롯·월드컵 등)은 돌아가는 연출 자체가 기능이라 이 설정에서 제외하고
(`.keep-motion`), 속도는 설정 화면의 **애니메이션 속도**로 조절한다. 애니메이션 효과를 꺼 둔
PC에서도 룰렛이 돌지 않고 결과로 바로 넘어가는 일이 없게 하기 위해서다.

애니메이션 효과를 꺼 둔 PC에서 켜진 상태를 확인하려면, 시스템 설정을 바꾸지 말고 창 설정의
`additionalBrowserArgs` 에 `--force-prefers-no-reduced-motion` 을 더한 JSON 을 만들어
`npm run tauri dev -- --config <그 파일>` 로 띄운다. 기본값
`--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection` 도 함께 적어야 한다.
`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 환경 변수는 Tauri 가 인자를 직접 넘기기 때문에 먹히지 않는다.

## 아직 없는 것

- **같이 고르기의 사내망 밖 접속** — 같은 망 안에서만 쓴다. 암호화(TLS)·입장 코드·브라우저용 참여
  페이지는 없다 (참여자도 점심픽을 실행해야 한다).
- FabriX 스트리밍(SSE)·도구 호출 — 이 앱은 한 번에 JSON 배열만 받으면 되므로 쓰지 않는다.
- Windows 외 플랫폼, 자동 업데이트, 코드 서명
